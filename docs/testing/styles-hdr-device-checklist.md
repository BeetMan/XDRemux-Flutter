# Styles HDR 缩略图 · 真机 A/B 测试清单（2026-10-26）

> 用途：验证本移植生成的 Apple 兼容 HEIC 在 iPhone / macOS Photos 里的**风格选择器可编辑性**与**线性缩略图观感（含 HDR 高光）**，并闭环「旋转样本方向」这一目前唯一未验证的代码路径。
> 执行者：用户（真机）；记录回传给开发（我）分析。
> 关联实现：`docs/modules/styles-pipeline.md` §4、`docs/research/gainmap-decode-feasibility-20261025.md`。

## 0. 结论判定口径

| 级别 | 含义 | 例子 |
|---|---|---|
| **P0 失败** | 文件不可用 | Photos 无法导入、打开报错、风格选择器消失/不可应用、编辑后无法保存 |
| **P1 明显问题** | 可用但观感/方向错误 | 缩略图横竖颠倒、风格预览与原生差异肉眼明显、HDR 高光完全没有 |
| **P2 轻微差异** | 可接受但需记录 | 阴影略亮/略暗、肤色轻微偏色、缩略图锐度不同 |

每项记录：**文件编号 / 设备与系统版本 / 结果（通过/P0/P1/P2）/ 截图编号 / 备注**。

| 编号 | 类型 | 用途 |

## 2. 开发侧可先跑的自动检查（执行者也可让开发代跑）

```bash
# 转换
styles_convert <源.heic> <输出.heic>

# 结构 + 方向判定
gm_probe <输出.heic>     # 期望：source orientation=.../presentation_oriented=...
lt_inspect <输出.heic> <thumb.hevc>

# 期望：hvcC profile_idc=2、bitDepthLuma/Chroma=10、chromaFormat=1
#       ffprobe: profile=Main 10, pix_fmt=yuv420p10le, 尺寸为 coded 方向长边 1024
ffprobe -v error -show_entries stream=profile,pix_fmt,width,height -of default=nw=1 <thumb.hevc>
```

自动检查清单：
- [ ] 转换返回 success，输出可被 `lt_inspect` 解析
- [ ] 线性缩略图是 Main10（profile_idc=2、bitDepth=10）
- [ ] `gm_probe` 的 `presentation_oriented` 与样本实际方向一致（S3 应为 true）
- [ ] 与修复前基线比：16-bit luma max/mean 不一致即记录（Normal 样本应基本一致）

## 3. iPhone Photos 测试步骤

对每个样本 S1–S8 重复：

- [ ] **A. 导入**：AirDrop / 文件 → Photos，确认出现在「最近项目」，无「无法导入」
- [ ] **B. 缩略图**：相册网格里缩略图**方向正确**（横拍不竖、竖拍不横）；观感与 R1 对比：高光（天空/灯）是否比 SDR 版本更有层次，而非一片死白
- [ ] **C. 打开大图**：无报错、无黑屏；放大到 100% 看高光过渡
- [ ] **D. 编辑 → 风格**：风格选择器**出现且可切换**；切到「鲜艳/自然/冷色」等能即时预览；应用后能保存
- [ ] **E. 还原**：重新打开文件，进入编辑 → 风格 → 「还原/移除风格」可用，且还原后图像正常
- [ ] **F. 另存/导出**：编辑后导出 JPEG/HEIC，导出文件在相册里正常显示
- [ ] **G. 重进**：杀掉 Photos 重新打开，文件仍在、缩略图仍正确（排除缓存假象）

对 S7（负样本）额外确认：
- [ ] 可以导入与编辑，但**不应**出现 HDR 高光增强；缩略图不应有异常亮斑

## 7. 注意事项

- **不要覆盖原图**；转换输出用不同文件名，导入 Photos 前可先改名（Photos 对同名文件会去重/缓存）。
- 若导入后看不到变化，先删除相册里旧副本再导入，排除缓存。
- 真机验收前请确保本机转换用的是**带 10-bit 归档**的构建（否则走 8-bit 回退，HDR 效果有差异，需在记录里注明构建类型）。
- P0 问题请附完整步骤与文件；P1/P2 附截图即可。
