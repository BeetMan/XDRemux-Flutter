## main 同步记录

已读取并同步 `origin/main` 的 v0.2.8 功能性更新（`b3aadae`、`f2d954c`）：移除顶栏 OPPO 快捷开关，将 HDR family、OPPO 兼容、相机尾部和严格 tmap 收入默认折叠的“高级模式”，并保留 v0.2.8 release notes。v0.3.0 的 Flutter/Rust/Installer 版本号未回退，P0.0 Swift backend 选项保留在 Apple 平台设置中。

## P0.0 已完成

- 新增 `ConversionBackend.rust` / `ConversionBackend.swift`；Rust 是默认值。
- 新增统一 request、progress、cancellation、error、output-validation contract。
- Rust adapter 保留原 FFI 参数、进度 handle、后台 isolate 和硬件编码路径。
- macOS/iOS 通过 `xdremux/swift-backend` MethodChannel 暴露 capability probe。
- Swift 选项仅在 macOS/iOS 显示；Windows/Android 不显示。
- 当前 Swift capability 明确为 unavailable：Swift Core 尚未作为嵌入式 Library/Framework 链接。
- 未添加 Swift CLI 子进程路径；未开放 Apple Photographic Styles 或 Apple Portrait UI。

取消语义目前是 best-effort：Rust FFI 没有中断原语，因此取消中的 Rust 调用会继续运行到 native 返回，Flutter 不会再把其结果标记为“已转换”。P0.1/P0.2 可在同一个 request id contract 上接入 Swift 原生取消和进度事件。

## macOS deployment target 评估

当前 Flutter macOS 工程的三个层面仍是 macOS 12：

- `apps/flutter/macos/Podfile`：`platform :osx, '12.0'`
- `apps/flutter/macos/Podfile` 的 `post_install`：Pods target 写入 `MACOSX_DEPLOYMENT_TARGET = '12.0'`
- `apps/flutter/macos/Runner.xcodeproj/project.pbxproj`：Runner Debug/Profile/Release 均为 `MACOSX_DEPLOYMENT_TARGET = 12.0`

上游 `v1.3.1` 的 `Package.swift` 明确声明 `.macOS(.v15)`。因此接入上游 `XDRemuxCore` / `XDRemuxAppleFeatures` 时，macOS 15 是当前 package contract 的最低 target；macOS 12 不能被视为兼容配置。下一步必须先决定并验证是否将 Runner、Podfile 和相关 Pods 统一提升到 macOS 15，再进行 Swift package 链接和 API smoke test。本阶段没有改动现有 deployment target。

即使提升到 macOS 15，也不能据此开放 iOS：上游 Core 使用 `Process`/`xcrun`，Portrait 使用外部 `zstd`，AppleFeatures 使用 Vision/CoreImage 及原生辅助资源，需单独做 iOS 编译与运行时 capability 验证。

## 未宣称的能力

P0.0 不代表 Swift 标准 HDR 已经可用，也不代表 iOS Apple 功能兼容。P0.1 必须先把 Swift Core 作为嵌入式 Library/Framework 接入并验证 macOS；iOS 还必须确认上游实现不依赖 `Process`、`xcrun`、外部 zstd 或 macOS 私有框架，之后才能提升 capability 并显示 Swift 功能。

已读取上游 `21Z121Z1/XDRemux` 的 `v1.3.1` tag（commit `6d99b568`）：其 `Package.swift` 当前只声明 `.macOS(.v15)`，并将 `XDRemuxCore`、`XDRemuxAppleFeatures` 和 CLI 分成 SwiftPM targets。当前 fork 没有这些 SwiftPM sources，因此本阶段只接入了 Library bridge contract；没有把上游独立历史整体合并，也没有将 macOS-only 源码误标为 iOS 可用。
