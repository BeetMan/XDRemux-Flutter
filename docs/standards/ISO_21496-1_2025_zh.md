# 引言 (Introduction)

为高动态范围（HDR）显示器制作的 HDR 图像可以提供更好的用户体验。其中一个挑战是确保在亮度余量有限或没有亮度余量的显示器（如标准动态范围（SDR）显示器）上显示 HDR 图像时，图像质量不会发生退化。

这可以通过创建一种标准化的解决方案来解决，该方案包括在同一个文件中存储一个基础图像和一个增益图，以便在基础表示和具有不同动态范围的替代表示之间进行转换。与存储这两种表示相比，该解决方案的优势在于通过最小化存储的冗余数据量来优化文件大小。它还避免了因使用独立文件而引起的物流管理问题。

包含像素的数据结构，通过合并文件中的基础图像和增益图获得

注 1：数据的结构符合本文档的要求。

# 3.2

# 基础图像 (baseline image)

包含像素和图像相关数据的数据结构，并在文件中存储为主图像

# 3.3

# 增益图 (gain map)

包含局部商（local quotients）的数据结构，用于在基础图像 $(3.2)$ 和替代图像 $(3.1)$ 两种图像表示之间进行转换

# 3.4

# 增益图应用空间 (gain map application space)

应用增益图 $(3.3)$ 的线性 RGB 颜色空间

注 1：对该空间进行缩放，使得 HDR 参考白（reference white）的 3 个 {R,G,B} 颜色组件中的每一个的值均为 1.0。其基色（colour primaries）要么是基础图像的基色，要么是替代图像的基色（见 5.3.4 和 B.2）。

# 3.5

# 高动态范围和宽色域编码 (high dynamic range and wide colour gamut encoding / HDR/WCG encoding)

能够包含更宽亮度变化的彩色图像编码，其动态范围显著高于标准动态范围编码的动态范围，且具有比标准色域编码更宽的颜色范围和更饱和的颜色

［来源：ISO/TS 22028-5:2023, 3.12］

# 3.6

# 高动态范围余量 (high dynamic range headroom / HDR headroom)

标称峰值亮度 $(3.10)$ 与 HDR 参考白亮度的比值，以 2 为底的对数表示

注 1：例如，在一个 HDR 图像中，其 HDR 参考白亮度为 203 尼特（nits），标称峰值亮度为 1624 尼特，则 HDR 余量将为 $\log_2 (1624/203)$，即 3。这意味着在 HDR 参考白之上具有 3 档（stops）的 HDR 余量。

# 3.7

# 高动态范围图像 (high dynamic range image / HDR image)

包含更宽亮度变化、其动态范围显著高于标准动态范围图像的动态范围的图像

［来源：ISO/TS 22028-5:2023, 3.13］

# 3.8

# HDR 参考白 (HDR reference white)

在受控照明下，置于场景中兴趣中心的 $100\%$ 朗伯（Lambertian）反射体通常会产生的 HDR 信号水平

注 1：在 HDR 内容中，这通常被称为漫反射白（diffuse white）。

注 2：HDR 参考白可用作 HDR 和 SDR 内容合成的锚点。HDR 参考白通常是标称峰值 SDR 所达到的 HDR 信号电平。

# 3.9

# 图像 (image)

包含像素和图像相关数据的数据结构

［来源：ISO/IEC 12087-1:1995, 3.1.3］

# 3.10

# 标称峰值亮度 (nominal peak luminance)

由指定的编码峰值白信号电平在显示器上产生的亮度

［来源：ISO/TS 22028-5:2023, 3.18］

注：符合本文档的软件应用可以忽略不满足这些要求的增益图。

# 4.2 增益图尺寸 (Gain map dimensions)

增益图包含与基础图像相关的增益信息。为了获得最大的准确性，增益图的长度和宽度应等于基础图像的长度和宽度。

或者，可以通过对增益图进行重采样（见 6.2.2 和 A.3.1）来修改增益图的尺寸，例如通过重采样因子 2（1/2 宽度和 1/2 高度）。

增益图的长度和宽度应使用元数据进行指示，如 5.2.2 中所定义。

注：对增益图应用重采样、有损压缩、色度子采样和其他存储优化算法可以减小其大小，但也可能会影响替代图像的图像质量。

# 4.3 增益图颜色组件 (Gain map colour components)

为了获得最大的准确性，增益图中的颜色组件数量应与基础图像中的颜色组件数量匹配：具有 3 个颜色组件的 RGB 图像的增益图也应具有 3 个 {R,G,B} 颜色组件。

或者，增益图可以存储单个无色（achromatic）组件。在这种情况下，相同的无色增益图将应用于 RGB 图像的 3 个 {R,G,B} 颜色组件中的每一个（见 6.3）。

组件数量应使用元数据进行指示，如 5.2.4 中所定义。

注：减少增益图中的颜色组件数量可能会影响替代图像中颜色还原的准确性。

# 4.4 增益图量化 (Gain map quantization)

增益图的位深度应为每个组件至少 8 位。增益图的位深度不需要与基础图像的位深度相匹配。

# ISO 21496-1:2025(en)

增益图的位深度应使用元数据进行指示，如 5.2.3 中所定义。

注：基础图像的位深度和增益图的位深度会影响替代图像表示的有效位深度。

# 4.5 方向 (Orientation)

增益图的方向应与基础图像的方向一致。

# 5 元数据 (Metadata)

# 5.1 概述 (General)

本章介绍了与增益图相关联的元数据。元数据提供了关于增益图以及两种图像表示的色度信息。元数据应按照附录 C 的规定存储在文件中。

# 5.2 增益图元数据 (Gain map metadata)

# 5.2.1 概述 (General)

以下元数据应与增益图一起存储。

# 5.2.2 尺寸 (Dimensions)

增益图尺寸元数据存储增益图的长度和宽度（见 4.2）。

注：增益图尺寸可以从相应图像文件格式的尺寸信息中派生。

# 5.2.3 量化 (Quantization)

量化元数据存储增益图的位深度（见 4.4）。

注：增益图量化可以从相应图像文件格式的编解码器位深度中派生。

# 5.2.4 增益图组件数 (Number of gain map components)

组件数量元数据存储增益图的颜色组件数（见 4.3）。其值应为 1（表示无色增益图）或 3（表示 RGB 增益图）。

# 5.2.5 逐组件元数据 (Per-component metadata)

# 5.2.5.1 元数据组件数 (Number of metadata components)

为以下逐组件元数据存储的组件数可以为 1 或 3。

如果组件数为 1，则相同的逐组件值将用于 RGB 图像的 3 个 {R,G,B} 颜色组件中的每一个（见 6.3）。

如果组件数为 3，则无论增益图的组件数是多少，都将为 RGB 图像的 3 个 {R,G,B} 颜色组件中的每一个使用单独的值。

# 5.2.5.2 逐组件最小值 (Per-component min values)

逐组件最小增益图值元数据存储 $\min(G)$，即对数底数为 2 的空间中增益图各组件的最小值。它用于归一化和反归一化增益图（见 6.2.1 和 A.3.2）。

# 5.2.5.3 逐组件最大值 (Per-component max values)

逐组件最大增益图值元数据存储 $\max(G)$，即对数底数为 2 的空间中增益图各组件的最大值。它用于归一化和反归一化增益图（见 6.2.1 和 A.3.2）。

对于每个组件，该组件的 $\max(G)$ 应大于或等于该组件的 $\min(G)$ 值（见 5.2.4）。

# 5.2.5.4 逐组件基础偏移常数 (Per-component baseline offset constants)

逐组件基础偏移元数据存储增益图各组件的基础偏移量 $k_{baseline}$。它用于避免在计算和应用增益图时出现数值问题（见 6.3 和 A.2），并能够提高基础图像中的低值。


# 5.2.5.5 逐组件替代偏移常数 (Per-component alternate offset constants)

逐组件替代偏移元数据存储增益图各组件的替代偏移量 $k_{alternate}$。它用于避免在计算和应用增益图时出现数值问题（见 6.3 和 A.2），并能够提高替代图像中的低值。

# 5.2.5.6 逐组件伽马值 (Per-component gamma values)

逐组件伽马值元数据存储应用于增益图各组件的 $\gamma$，作为预压缩步骤（见 6.3 和 A.3.3）。其值应大于零。

# 5.2.6 基础高动态范围余量 (Baseline high dynamic range headroom)

基础 HDR 余量元数据存储 $H_{\mathrm{baseline}}$，即基础图像的 HDR 余量。

注：$H_{\mathrm{baseline}}$ 是不应用增益图时的 HDR 余量值（见 6.3）。

# 5.2.7 替代 HDR 余量 (Alternate HDR headroom)

替代 HDR 余量元数据存储 $H_{\mathrm{alternate}}$，即替代图像的 HDR 余量。$H_{\mathrm{alternate}}$ 不应等于 $H_{\mathrm{baseline}}$（见 5.2.5）。

注：$H_{\mathrm{alternate}}$ 是完全应用增益图时的 HDR 余量值（见 6.3）。

# 5.2.8 版本标签 (Version tag)

版本标签元数据存储增益图的版本。详情请参阅 C.2.2 和 C.2.3 中的 minimum_version 和 writer_version。

对于本文档的第一版，minimum_version 应为 0，writer_version 应大于或等于 0。

# 5.3 色度元数据 (Colorimetry metadata)

# 5.3.1 概述 (General)

色度元数据提供了关于两种图像表示的色度信息，以及应在其中应用增益图的颜色空间。颜色转换应按照附录 B 的规定进行。

# 5.3.2 基础图像色度元数据 (Baseline image colorimetry metadata)

应包含指定基础图像颜色编码的色度元数据，例如符合 ICC.1:2022 的包含 CICP 标签的 ICC 配置文件，或符合 ISO/IEC 23091-2/ITU-T H.273 的 CICP 元数据（即用于视频信号类型识别的独立于编码的码点）。另见 C.4.4。

# 5.3.3 替代图像色度元数据 (Alternate image colorimetry metadata)

宜包含指定替代图像颜色编码的色度元数据，例如符合 ICC.1:2022 的包含 CICP 标签的 ICC 配置文件，或符合 ISO/IEC 23091-2/ITU-T H.273 的 CICP 元数据（即用于视频信号类型识别的独立于编码的码点）。另见 B.2 和 C.4.7。

如果不存在替代图像的色度元数据，则替代图像颜色空间应与基础图像颜色空间相同。

# 5.3.4 增益图应用空间基色元数据 (Gain map application space colour primaries metadata)

增益图应用空间基色元数据指示增益图应用空间的基色是基础图像的基色还是替代图像的基色（见 B.2）。

注：例如，在基础图像是编码为 sRGB（如 IEC 61966-2-1 中所指定）的 SDR 表示，而替代图像是编码为 ISO/TS 22028-5 中所指定的 HDR 表示的文件中，如果增益图应用空间基色元数据指示了 ISO/TS 22028-5 颜色空间，则增益图应用空间的基色将是 ISO/TS 22028-5 中指示的基色。

# 6.2 处理增益图 (Processing the gain map)

# 6.2.1 增益图反归一化 (Unnormalizing the gain map)

增益图在归一化和伽马处理后进行存储（见 A.3）。应使用逐组件的最小值 $\min(G)$、最大值 $\max(G)$（见 5.2.5.2 和 5.2.5.3）以及逐组件的伽马值 $\gamma$（见 5.2.5.6）对增益图进行反归一化，对每个颜色组件执行逆变换，如公式 (1) 所示：

$$
G = \left[ \max (G) - \min (G) \right] \times \left(G _ {\text {normalized} \_ \gamma}\right) ^ {\frac {1}{\gamma}} + \min (G) \tag {1}
$$

其中 $G$ 是以对数底数为 2 表示的增益图颜色组件。

# 6.2.2 增益图重采样 (Resampling the gain map)

当存储的增益图尺寸与基础图像的尺寸不一致时（见 4.2），应进行重采样步骤，使得重采样后的增益图长度和宽度等于基础图像的长度和宽度。

注 1：对增益图进行重采样时，相位偏移（phase offset）可能会影响增益图的图像质量。首选的相位偏移是同位（co-sited）模式（即 ITU-T H.265 中定义的 ChromaLoc 类型 2）。

注 2：重采样应在对增益图进行反归一化之后应用，以与 A.3 中的操作顺序保持一致。

注 3：替代图像的长度和宽度等于基础图像的长度和宽度。

# 6.3 应用增益图 (Applying the gain map)

在线性 RGB 增益图应用空间中，通过将线性化基础图像与增益图结合来获得线性替代图像表示，对于每个颜色组件，其计算方法如公式 (2) 所示：

$$
\text { Alternate } = \left(\text { Baseline } + k _ {\text { baseline }}\right) \times 2 ^ {(W \times G)} - k _ {\text { alternate }} \tag {2}
$$

其中 Alternate 是替代 RGB 线性图像的 $\{R,G,B\}$ 中的颜色组件，Baseline 是基础 RGB 线性图像的 $\{R,G,B\}$ 中的颜色组件，$G$ 是 RGB 增益图的 $\{R,G,B\}$ 中的颜色组件，$k_{baseline}$ 是基础图像的逐组件偏移常数（见 5.2.5.4），$k_{alternate}$ 是替代图像的逐组件偏移常数，而 $W$ 是权重因子。

权重因子 $W$ 可用于将增益图缩放到范围 $[H_{\mathrm{baseline}}, H_{\mathrm{alternate}}]$ 内的目标余量值 $H_{\mathrm{target}}$。$W$ 是 $H_{\mathrm{baseline}}$、$H_{\mathrm{alternate}}$ 以及 $H_{\mathrm{target}}$ 的函数，其计算方法如公式 (3) 所示：

$$
W = \operatorname{sign} \left(H _ {\text { alternate }} - H _ {\text { baseline }}\right) \times \operatorname{clamp} \left(\frac {H _ {\text { target }} - H _ {\text { baseline }}}{H _ {\text { alternate }} - H _ {\text { baseline }}}, 0, 1\right) \tag {3}
$$

注 1：$\operatorname{sign}(x)$ 函数返回一个指示 $x$ 符号的数值，$\operatorname{clamp}(x,0,1)$ 函数将 $x$ 的值限制在 0 到 1（含）之间。

注 2：如果 $G$ 是单组件（无色/单色）增益图（见 4.3），则应将相同的无色增益图应用于 RGB 基础图像的 3 个 {R,G,B} 颜色组件中的每一个。

注 3：对于显示器 HDR 余量处于 $[H_{baseline}, H_{alternate}]$ 范围内的情况，可以缩放增益图以生成具有与显示器 HDR 余量相匹配的目标 HDR 余量值 $H_{target}$ 的替代图像。

注 4：$H_{\mathrm{baseline}}$ 是不应用增益图（$W = 0$）时的 HDR 余量值，$H_{\mathrm{alternate}}$ 是完全应用增益图（$W = -1$ 或 $W = 1$）时的 HDR 余量值。

# A.2 计算增益图 (Computing the gain map)

增益图是两种呈现方式的对数编码比率或商。它是由图像的 Baseline（基础）表示和 Alternate（替代）表示通过两者的除法并对结果取对数而获得的，如公式 (A.1) 所示：

$$
G = \operatorname{sign} \left(H _ {\text { alternate }} - H _ {\text { baseline }}\right) \times \log_ {2} \left(\frac {\text { Alternate } + k _ {\text { alternate }}}{\text { Baseline } + k _ {\text { baseline }}}\right) \tag {A.1}
$$

其中 $k_{alternate}$ 为各组件的替代偏移量（见 5.2.5.5 和 6.3），$k_{baseline}$ 为各组件的基础偏移量（见 5.2.5.4 和 6.3）。

这两种图像表示处于相同的线性 RGB 颜色空间中，该空间经过缩放，使得 HDR 参考白的 3 个 {R,G,B} 颜色组件中的每一个的值均为 1.0（见 B.2）。

注：由于增益图使用以 2 为底的对数，因此它具有直观的摄影学意义：它大约是两种图像表示之间以光圈档数（stops）或曝光值（EV）表示的差异。未归一化增益图中像素值为 0 意味着图像表示中的相应像素大致相同。值为 +1 意味着替代表示中的像素比基础表示中的相应像素亮大约 1 档。

# A.3.3 增益图归一化 (Normalizing the gain map)

逐组件的伽马值 $\gamma$ 作为元数据存储，如 5.2.5.6 中所定义。

# C.2 二进制元数据载荷 (Binary metadata payload)

# C.2.1 概述 (General)

增益图元数据按照以下结构以二进制形式进行存储。无论容器格式的字节顺序如何，该数据结构的字节顺序均为大端序（big-endian）。对于使用少于一整字节的字段，同样也是如此，其中各比特位按从最高有效位到最低有效位的顺序进行选择。

元数据结构在结构结束之后可以具有填充数据（padding data）。元数据结构在识别的字段之后也可以具有未来的可选元数据。解析器应在最后一个识别的元数据字段之后停止读取，并忽略所有剩余数据（见 C.2.2 中 minimum_version 字段的语义）。

# C.2.2 语法 (Syntax)

```txt
struct GainMapChannel {
    int(32) gain_map_min_numerator;
    unsigned int(32) gain_map_min_denominator;
    int(32) gain_map_max_numerator;
    unsigned int(32) gain_map_max_denominator;
    unsigned int(32) gamma_numerator;
    unsigned int(32) gamma_denominator;
    int(32) base_offset_numerator;
    unsigned int(32) base_offset_denominator;
    int(32) alternate_offset_numerator;
    unsigned int(32) alternate_offset_denominator;
}

struct GainMapVersion {
    unsigned int(16) minimum_version;
    unsigned int(16) writer_version;
}

aligned(8) class GainMapMetadata {
    GainMapVersion version;
    if (minimum_version == 0) {
    unsigned int(1) is_multichannel;
    unsigned int(1) use_base_colour_space;
    unsigned int(6) reserved;
    // nonparsable variable
    int channel_count = (is_multichannel)*2 + 1;
    unsigned int(32) base_hdr_headroom_numerator;
    unsigned int(32) base_hdr_headroom_denominator;
    unsigned int(32) alternate_hdr_headroom_numerator;
    unsigned int(32) alternate_hdr_headroom_denominator;

    GainMapChannel channels[channel_count];
    }
} 
```

# C.2.3 语义 (Semantics)

minimum_version 是解析器解析元数据载荷并应用增益图所需的最低版本。本规范的后续更新可能会向 GainMapMetadata 结构中添加可选的新元数据。如果这些更改是以向后兼容的方式进行的（通过仅追加而不更改现有字段的顺序），则所需的 minimum_version 可以保持不变。解析器遇到无法识别的 minimum_version 时应忽略增益图元数据载荷并显示基础图像。在本版规范中，minimum_version 应为 0。

writer_version 是写入器使用的元数据结构的版本。该值应大于或等于 minimum_version。

is_multichannel 等于 1 指定增益图逐通道元数据的通道数为 3，而值为 0 指定通道数为 1。这可能与 5.2.5.1 中所述的增益图中的实际通道数不同。

use_base_colour_space 等于 1 指定基础图像的颜色空间的基色应被用于增益图应用空间，如 5.3.4 中所述。值为 0 指定替代图像的颜色空间的基色用于增益图应用空间。

base_hdr_headroom_numerator 和 base_hdr_headroom_denominator 分别指定基础 HDR 余量（5.2.6）的分子和分母。

base_hdr_headroom_denominator 不应为 0。基础 HDR 余量值计算为无符号有理数 base_hdr_headroom_numerator / base_hdr_headroom_denominator。

alternate_hdr_headroom_numerator 和 alternate_hdr_headroom_denominator 分别指定替代 HDR 余量（5.2.7）的分子和分母。

alternate_hdr_headroom_denominator 不应为 0。基础 HDR 余量值计算为无符号有理数 alternate_hdr_headroom_numerator / alternate_hdr_headroom_denominator。

channels 指定逐通道的元数据。如果是多通道，则通道的顺序为 R、G、B。

gain_map_min_numerator 和 gain_map_min_denominator 分别指定逐组件增益图最小值（5.2.5.2）的分子和分母。

gain_map_min_denominator 不应为 0。逐组件增益图最小值计算为有符号有理数 gain_map_min_numerator / gain_map_min_denominator。

gain_map_max_numerator 和 gain_map_max_denominator 分别指定逐组件增益图最大值（5.2.5.3）的分子和分母。

gain_map_max_denominator 不应为 0。逐组件增益图最大值计算为有符号有理数 gain_map_max_numerator / gain_map_max_denominator。

gamma_numerator 和 gamma_denominator 分别指定逐组件伽马值（5.2.5.6）的分子和分母。gamma_numerator 不应为 0。

gamma_denominator 不应为 0。逐组件伽马值计算为无符号有理数 gamma_numerator / gamma_denominator。

base_offset_numerator 和 base_offset_denominator 分别指定逐组件基础偏移常数（5.2.5.4）的分子和分母。

base_offset_denominator 不应为 0。逐组件基础偏移常数计算为有符号有理数 base_offset_numerator / base_offset_denominator。

alternate_offset_numerator 和 alternate_offset_denominator 分别指定逐组件替代偏移常数（5.2.5.5）的分子和分母。

alternate_offset_denominator 不应为 0。逐组件替代常数计算为有符号有理数 alternate_offset_numerator / alternate_offset_denominator。

# C.4 JPEG

# C.4.1 概述 (General)

本节描述了如何使用 CIPA 多图片格式（CIPA DC-007）在 JPEG 中存储 21496-1 增益图。

注：由于 JPEG 文件仅支持每通道 8 位，本章解释的主要使用场景是 8 位 SDR 基础图像（存储为多图片格式基础图像）和 8 位增益图图像（存储为多图片格式单张图像）。

# C.4.2 识别 (Identification)

如果 JPEG 文件满足 C.4 所有子条款的要求，则认为该文件符合本规范。

注：查看文件是否为包含 21496-1 增益图的 JPEG 的简单方法是寻找有效的基础图像（C.4.3）。

# C.4.3 基础图像 (Baseline image)

基础图像应为符合 CIPA DC-007 的基础图像。C.4 中定义的基础图像应包含 C.4.6 中描述的 APP2 标记，其中“元数据”（Metadata）字段设置为 C.2.2 中的 GainMapVersion 二进制数据结构，而不是完整的 GainMapMetadata 结构。

注：符合 CIPA 的多图片格式基础图像是符合 Exif（CIPA DC-008）的 JPEG 图像，从文件的第一个字节开始。

# C.4.4 基础图像颜色空间 (Baseline image colour space)

MPF 基础图像的颜色空间可以使用 Exif（CIPA DC-008）ColorSpace（A001.H）标记或 ICC 配置文件来指定，具体如下：

— 如果 Exif ColorSpace = 1（sRGB），则基础图像的颜色空间应为 CIPA DC-008 中指定的 sRGB。

— 如果 Exif ColorSpace 不为 1，且基础图像中存在 ICC 配置文件，则应使用该 ICC 配置文件来标识基础图像的颜色空间。如果基础图像是 HDR，则 ICC 配置文件应包含 CICP 标签。

— 如果 Exif ColorSpace 不为 1，且基础图像中不存在 ICC 配置文件，则假定基础图像的颜色空间为 sRGB。

# C.4.5 增益图像素数据 (Gain map pixel data)

增益图像素数据以 JPEG 压缩图像的形式存储，并使用 CIPA DC-007 多图片格式附加到基础图像中。基础图像被指定为第一张单张图像。

增益图单张图像应包含 C.4.6 中描述的 APP2 标记。如果增益图有三个通道，则在与 RGB 进行相互转换时，应使用 ISO/IEC 10918-5 中描述的矩阵系数。

# 引言 (Introduction)

为高动态范围（HDR）显示器制作的 HDR 图像可以提供更好的用户体验。其中一个挑战是确保在亮度余量有限或没有亮度余量的显示器（如标准动态范围（SDR）显示器）上显示 HDR 图像时，图像质量不会发生退化。

这可以通过创建一种标准化的解决方案来解决，该方案包括在同一个文件中存储一个基础图像和一个增益图，以便在基础表示和具有不同动态范围的替代表示之间进行转换。与存储这两种表示相比，该解决方案的优势在于通过最小化存储的冗余数据量来优化文件大小。它还避免了因使用独立文件而引起的物流管理问题。
