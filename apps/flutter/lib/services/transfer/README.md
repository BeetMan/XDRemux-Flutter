# Dart transfer worker, application controller and checkpoint handoff

`TransferService` is an optional capability. Construction and the home queue's `TransferQueue.register` do not load native code or start a listener. Explicitly call `start` with the application support directory; it starts a persistent isolate that loads only the transfer library. The existing image FFI and conversion service remain independent. Windows loads `xdremux_transfer.dll` beside the executable; Android uses `libxdremux_transfer.so`. Missing libraries, unsupported platforms and ABI <1.3 return an unavailable capability, presented as an actionable error in the P2.2 page.

```dart
final support = await getApplicationSupportDirectory();
final transfer = TransferService();
final capability = await transfer.start(supportRoot: support.path);
if (!capability.available) {
  await transfer.dispose();
  return;
}
// Production callers use TransferController / TransferPage for confirmation.
final inbox = await transfer.command({'command': 'receipts', 'limit': 64});
final intake = TransferIntake(transfer); // uses the registered home queue
final ack = await intake.importReceipt(selectedReceiptId);
// When leaving/stopping, finish external reads, then:
await transfer.dispose();
```

`command` follows the [native JSON contract](../../../../../crates/xdremux-transfer-ffi/README.md). `drainEvents` returns bounded events and a `resync` flag; when set, rescan native snapshot/file/receipt pages and apply subsequent events, using instance IDs and file IDs. The worker polls every 50 ms, even while copying, so operation results do not depend on UI polling. Buffered UI events are capped at 256 and 2 MiB. Native results are correlated by operation ID; missing results are queried from the bounded native operation cache without replaying the original mutation. After 30 seconds without an answer, return `outcome_unknown` with its operation ID and require reconciliation. Unknown lease operations trigger stop to revoke potentially orphaned leases.

There are at most 24 normal pending native calls, 32 including cancellation/cleanup, and 40 owner-side RPCs. Stop has a separate path. Only one copy runs per worker. Dispose blocks new work, waits for its current copy and lease cleanup, then stops/releases the native handle and waits for isolate exit. Repeated dispose shares the same future. Native startup/disk I/O is allowed to finish; there is no hard shutdown deadline. Callers must await dispose rather than kill the isolate.

The controller treats completed/failed transfer snapshots and ACKed/committed files as authoritative over queued progress. Live progress is bounded by file size and cannot regress from an older event. A progress event for a failed file in a still-active session triggers snapshot reconciliation, allowing a peer's same-session checksum retry without reviving the file from an old event alone. Native file errors remain separate from batch cancellation/timeout. See [terminal state validation](../../../../../docs/testing/local-transfer-terminal.md).

The checkpoint handoff is explicit:

1. `prepareInput` acquires a native read lease and checks service-volume free space for the declared bytes plus 64 MiB. Inbox and copies must remain under the same application support filesystem. This is advisory; the worker maps write failures to redacted errors. The check covers the extra input copy; conversion/output and user-selected export destinations need their own space check in P2.2.
2. Accept only HEIC/HEIF/JPEG names with matching shallow container signatures. This is not a media decoder validation; the existing classifier/admission rules decide whether the file can join the queue. MOV and other opaque files remain in the inbox.
3. Stream the leased `data` file to a private staging bucket, hashing incrementally, checking exact length and SHA-256, flushing, and publishing the completed directory as `xdremux_checkpoint_inputs/transfer-<receiptUUID>/<originalName>`. Never load a whole payload into Dart/UI memory. Same-name receipts use different buckets; repeat imports verify the existing copy and marker before reusing it. Owned partial staging is cleaned on the next prepare; unknown contents/links fail closed.
4. `TransferIntake` calls the queue callback. The home queue reuses existing classification, portrait/Huawei policy and output planning, bypasses filename-based donor substitution for transfer imports, and persists a checkpoint **before** ACK. ACK states are added / duplicate / unsupported / rejected / failed. Successful ACKs require a queue ID. Existing converted-image skip policy can reject an otherwise valid received file.
5. The receipt marker records the ACK. If a crash/persistence error occurs after queue insertion, keep the copy; retry uses its deterministic path and asks the queue again. A previous marker alone is not evidence the current queue contains the item. The queue restores from its checkpoint and deduplicates by input path. Valid abandoned marker writes can be retried. Error strings are stable codes and omit paths/PIN/native exceptions.

The input file and marker belong to checkpoint storage after publication. Inbox deletion cannot remove them. Conversion output defaults to a separate `xdremux_transfer_outputs/<receiptUUID>/` directory (or the user's configured output/mobile fallback), including after settings refresh/restart. Import/callback/ACK and checkpoint cleanup share one serialized ownership gate; queue editing/start is blocked during handoff. Specific queue removal cleans the input/marker, while bulk picker cleanup skips transfer buckets. Rejected/prepared copies are retained for retry; a user-facing retention/orphan management screen remains P2.2 work. No automatic gallery import or deletion occurs.

P2.2 adds `TransferController` and `TransferPage`. The toolbar and original/converted-file action menus open the page on Windows/Android. Literal IP/port probe displays the complete certificate fingerprint; sending metadata requires explicit confirmation. Remembering a fingerprint remains advisory and never auto-accepts incoming files. Incoming offers require acceptance, progress uses file IDs, and committed receipts support queue import, verified export and managed deletion. Snapshot reconciliation preserves loaded receipt pages and out-of-window commits; overflow scans all receipt pages. P2.3 loads all native file pages (up to 1024), aggregates progress across the batch and expands the preview in 64-file steps.

Reconnecting clears the selected peer before probing, including failure or cancellation. Endpoint and PIN fields are disabled while the page is working; confirmed badges and send/retry actions use the controller's current confirmation set, so forgetting fingerprints immediately revokes them. `send` takes an immutable copy of the selected peer and source path list before async startup, then rechecks confirmation immediately before dispatch. This does not cancel a send already submitted to the worker; use explicit transfer cancellation for that. The native certificate pin and retry identity checks remain unchanged. See [confirmation validation](../../../../../docs/testing/local-transfer-confirmation.md).

`enableReceiving` binds LAN only after user action (default 53319, editable). Sending/inbox operations use loopback when reception is off. Leaving the page, Android pause/detach, tray exit and Windows close stop the service. Export/import reads finish and release leases before native disposal. Returning to the foreground never automatically re-enables LAN. Android file/document pickers explicitly await stop before launch, independently of OEM lifecycle delivery; the user must explicitly resume receiving afterwards. Android SAF export uses the filename's MIME (including explicit MOV/HEIC/HEIF mapping), consumes a one-shot selected URI, streams native 64 KiB chunks and verifies provider readback. Failure preserves the inbox; a provider can leave a partial external document. This is generic document export, not gallery insertion.

`TransferDesktopLifecycle` shares pending cleanup between Windows close and tray exit. Native `WM_CLOSE` stays blocked until Dart approves it; an error or unhandled reply clears the pending request so a later user close can retry. Approval failure also permits a fresh cleanup attempt, including any receiver started since the failed attempt. There is no forced shutdown deadline: managed reads and native disposal must finish. The release desktop fixture in `tool/transfer_desktop_close_app.dart` verifies actual window close, a held receipt lease, partial upload cleanup, and same-root recovery; see [P3.2 validation](../../../../../docs/testing/local-transfer-p32.md).

Build the optional library with `tools/native/build-transfer.ps1 -Platform windows|android`, then build Flutter normally. Windows CMake and Android Gradle detect the canonical crate target outputs; explicit overrides are `XDREMUX_WINDOWS_TRANSFER_DLL` and `XDREMUX_ANDROID_TRANSFER_SO`. Missing optional libraries do not invoke Cargo or break ordinary image builds. LocalSend's Apache license is copied into the corresponding bundle. The isolated release integration target additionally uses `XDREMUX_TRANSFER_TEST_APP=true` to install `.transferdev` alongside the real app; never set this for production. See [P2.2 validation](../../../../../docs/testing/local-transfer-p22.md).

Every controller `stop()` revokes earlier pending starts, including a receive request still waiting for shared read cleanup. Startup rechecks that cancellation after directory selection, native startup and initial refresh. A cancelled call reports `closed`; already-started native initialization is awaited and disposed before stop completes, with no forced worker kill or automatic LAN restart. A later explicit action can start a new runtime using the same storage/identity. See [startup cancellation validation](../../../../../docs/testing/local-transfer-startup.md).

Discovery, polling and query replies also belong to a service instance and stop generation. Late errors cannot stop a replacement runtime or clear its peers; old poll/refresh completion cannot clear a replacement task slot. Stop detaches old snapshot/inbox queries so explicit startup loads its own state; queued inbox reads never cross into the replacement service. Android multicast operations are ordered, with stop's release after any pending acquire, and stale discovery cannot release the new receiver's lock. Managed file reads still finish before native disposal. The controlled reply/lock tests and pending device checks are recorded in [runtime handoff validation](../../../../../docs/testing/local-transfer-runtime-boundary.md).

Within one runtime, explicit discovery refresh supersedes earlier discovery status replies and nonterminal errors. Repeated refresh requests share one pending announcement; polling skips discovery status while it is pending, but still consumes events and refreshes receipts/snapshots. Runtime `closed`/`worker_stopped` errors remain terminal and require explicit restart. An old discovery completion cannot clear a replacement task slot. See [discovery ordering validation](../../../../../docs/testing/local-transfer-discovery-ordering.md) for the controlled tests and remaining device checks.

`tool/transfer_network_host.py` prepares a staged Windows-native-to-Android interruption check with nonce-bound manual confirmation, network-down, reconnect and retry checkpoints. It never changes OS network settings or auto-selects a reconnected ADB device. Its self-test uses owned loopback services and an injected opaque-relay cut; that result is explicitly `realNetworkValidation=not_run`. The manual workflow, one-direction scope and settings/background-policy limitations are in [network script preparation](../../../../../docs/testing/local-transfer-network.md).

Validation:

```powershell
flutter test --no-pub test/transfer_copy_test.dart
dart run tool/transfer_worker_smoke.dart ABSOLUTE_DLL_PATH REPORT_PATH [ABI_1_0_DLL_PATH]
# Optional real classifier/home queue test; fixture must be a readable HEIC:
$env:XDREMUX_TRANSFER_QUEUE_FIXTURE = 'ABSOLUTE_HEIC_PATH'
flutter test --no-pub test/transfer_queue_widget_test.dart
```

The DLL smoke uses real loopback HTTPS and persistent worker isolates, verifies copied hashes, tests unavailable/old ABI, operation errors, ACK loss, same-name receipts, native inbox deletion, stopping during a 64 MiB copy, and exact root/port reuse. The optional widget test uses the existing image classifier/home queue with a copied HEIC fixture; it disables the existing “skip converted” setting for that admission test. It never modifies the supplied fixture. Native payload fixtures and local reports are not committed.

P2.3 starts bounded IPv4 multicast discovery only while receiving. The selected local IPv4 interface also controls the HTTPS bind address; All networks includes VPN/virtual interfaces. Android holds a non-reference-counted multicast lock, released on stop, Activity.onStop and destruction. Discovery failure leaves direct IP/port usable. Discovered hints require HTTPS certificate verification, a fresh selection-time probe and explicit full-fingerprint confirmation. UI polling reads discovery snapshots at most once per second.

Failed outgoing jobs expose an explicit retry action for the same confirmed fingerprint. ACKed files are excluded; unchanged sources are required and lost ACKs may cause duplicates. PINs must be entered again. Retry plans and displayed transfer history are cleared on service stop; persistent inbox receipts remain. Sibling paths use `send_batch` to stay below the 64 KiB JSON input bound; other oversized selections fail with `batch_too_large` before submission. See [P2.3 validation](../../../../../docs/testing/local-transfer-p23.md).

P3.1 consumes terminal runtime events before discovery queries. A stopped/fatal event, a closed command or a terminated worker clears stale reception and requires explicit restart; no automatic LAN reopening or mutation replay occurs. Disabled discovery clears peers and releases the Android multicast lock while leaving HTTPS reception available. Windows selected-port WSAEACCES is surfaced as an occupied/unavailable port. Controlled fault evidence and its network-simulation limits are in [P3.1 validation](../../../../../docs/testing/local-transfer-p31.md).

`dart run tool/transfer_fault_smoke.dart ABSOLUTE_DLL REPORT LOCAL_PRIVATE_IPV4` exercises actual DLL/worker port collision/reuse, an unavailable discovery interface, manual HTTPS fallback, discovery recovery and explicit retry at a new endpoint with the same identity. It creates only temporary synthetic fixtures; the selected interface is used for a short multicast announcement. It does not change OS interfaces, firewall or permissions.
